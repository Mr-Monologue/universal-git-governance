## Task 003 决策建议（未批准）

| 项目 | 当前建议 | 选项与权衡及本轮建议 | 是否经用户批准 |
| --- | --- | --- | --- |
| 大括号 | K&R / Attach | Allman 便于垂直对齐，Attach 更紧凑；文中部分片段仍是换行大括号，与配置不一致。保留候选配置，不改写历史片段或既有项目 | 否 |
| 缩进 | 4 空格、UseTab Never | Tab 可由编辑器调整宽度，但原 Checklist 同时写 Tab 和 4 空格。建议新模板暂用空格以减少显示差异 | 否 |
| 行宽 | 100 列 | 80 列更适合窄窗口，100 列容纳较长 API 名；建议项目选择其一并冻结工具版本，保留原 80 列偏好待确认 | 否 |
| 公共/私有命名、typedef | 模块前缀、snake_case；typedef 后缀由项目选定 | 公共重命名涉及 ABI/API，私有命名可局部统一；g_/p_/pf_ 与 _T/_t 不强制淘汰。建议继承项目规则，不批量改名 | 否 |
| C11/C99/C23 | 新项目 C11，受限项目 C99，C23 显式选择 | C99 兼容旧编译器；C11 能力依工具链；C23 需验证编译器与库。建议先测实际目标工具链，不全局切换标准 | 否 |
| Doxygen 文本语言 | 中文，项目可覆盖 | 中文便于本地维护，英文便于跨团队公开库；建议采用项目主语言。Doxygen 强制本身已确定，文本语言尚未冻结 | 否 |
| 静态检查/MISRA | 分层启用 | 普通项目先编译告警和测试，再选静态分析；安全项目另需标准版本、工具配置、偏离记录与审查证据。建议按风险选型，不能以模板通过替代合规证据 | 否 |

本轮仅提出建议，所有风格仍未批准；条件比较方向和文件头元数据沿用上表待决状态。
