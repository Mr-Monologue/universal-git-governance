# 嵌入式 C 代码审查清单 v0.1

> 对应 [`C_CODING_STANDARD.md`](C_CODING_STANDARD.md)。审查范围仅为当前任务实际修改的代码、其受影响接口和必要的回归测试；第三方生成代码按项目批准的例外处理。

## A. 文件与接口

- [ ] `.c/.h` 的职责划分合理，公开 API 位于 `.h`，私有实现位于 `.c`。
- [ ] 头文件可单独包含，具有唯一 include guard，包含足够的直接依赖。
- [ ] 新增公开符号具有模块前缀；未无授权地修改现有 ABI/API。
- [ ] 所有新建 `.c/.h` 有 `@file`、`@brief` 的 Doxygen 文件头。
- [ ] 所有新增/变更的公开函数有 Doxygen API 契约，参数、返回、单位、有效范围与副作用准确。
- [ ] 对公开结构体/枚举及含义不明显的字段有 Doxygen 说明。
- [ ] ISR、任务、DMA 的上下文、并发及阻塞限制被准确说明。

## B. 数据和内存

- [ ] 关键整数转换前验证范围；无有符号溢出、非法移位、除零等风险。
- [ ] 数组/缓冲区操作验证大小；字符串终止与截断处理正确。
- [ ] 指针有效性有契约依据；所有权和生命周期明确。
- [ ] DMA 缓冲区的对齐、缓存一致性及生命周期明确。
- [ ] 物理量单位、峰值/RMS 等约定被统一描述；涉及公式先定义符号。

## C. 实时与并发

- [ ] ISR/硬实时路径未引入不可控阻塞、动态分配、慢速日志。
- [ ] 共享变量具有同步策略，未误用 `volatile` 作为线程同步手段。
- [ ] 已确认定时、调度、任务栈、资源锁定符合项目约束。
- [ ] RTOS API 在正确的任务或 ISR 上下文调用。

## D. 控制流与错误处理

- [ ] `switch` 及错误分支完整且具有可观测结果。
- [ ] 成功/失败/未初始化/边界输入的行为清楚；释放和回退路径完整。
- [ ] 失败时无关键错误被静默丢弃，未强制 ISR 打印日志。

## E. 可维护性与验证

- [ ] 仅修改本次任务授权的文件；未触及无关格式化。
- [ ] 采用仓库批准的 `.clang-format` 配置。
- [ ] 编译/格式/测试/Doxygen 检查已执行，并记录真实命令及结果；未执行项说明原因。
- [ ] 未伪造文件作者、许可证、日期或测试证据。
- [ ] 涉及 MISRA 的项目已说明版本、偏离与独立工具检查情况；无不实合规声明。
